# מחולל מבחנים במתמטיקה — גרסה 5.5.0

אפליקציית Streamlit שהופכת צילומי שאלות לשלושה מסמכים: **טופס בחינה**, **פתרון מלא** ו**מחוון בדיקה**. כל מסמך מופק כ-Word לעריכה (עם משוואות Word אמיתיות) וכ-PDF להדפסה בגודל A4.

## קבצים
| קובץ | תפקיד |

| `app.py` | ממשק המשתמש (5 שלבים) |

| `diagram_engine/` | מנוע שחזור שרטוטים דטרמיניסטי: מבנה נתונים, ניתוח טקסט, אילוצים, אימות, ציור, השוואה, החלטה |
| `diagram_ui.py` | מסך ביקורת השרטוטים של המורה (מקור מול שחזור, אישור ועריכה) |

## התקנה מקומית
```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux
pip install -r requirements.txt
streamlit run app.py
```
כדי להפיק PDF מקומית צריך להתקין LibreOffice כך שהפקודה `soffice` זמינה ב-PATH. ב-Linux חשוב להתקין גם את `libreoffice-math`, אחרת הנוסחאות ייעלמו מה-PDF.

## Streamlit Community Cloud
1. מעלים את כל התיקייה ל-GitHub, כולל `packages.txt` ו-`.streamlit/`.
2. מגדירים את `app.py` כ-entrypoint.
3. ב-Secrets מוסיפים:
```toml
GEMINI_API_KEY = "YOUR_KEY"
GEMINI_MODEL = "gemini-3.8-flash"   # אופציונלי
```
אם המודל שהוגדר אינו זמין למפתח, המערכת עוברת אוטומטית למודל Flash זמין אחר (3.7 / 3.6 / 3.5).

## זרימת העבודה
1. **הגדרות**: פרטי בית הספר, שכבה, רמה, שפה, מבנה בחירה ולוגו. ההוראות לתלמיד מתעדכנות אוטומטית לפי מבנה הבחינה, כל עוד לא נערכו ידנית.
2. **תמונות**: העלאה, מצלמה או הדבקה. לכל תמונה יש **חיתוך**, **מחיקת סימנים** (מלבן או מכחול), **סיבוב** ב-90° או 180° או סיבוב עדין, **יישור אוטומטי**, ביטול פעולה וחזרה למקור. כל הפעולות נשמרות ברזולוציה המלאה.
3. **פענוח**: קריאה נפרדת ל-Gemini לכל שאלה, במקביל, עם ניסיונות חוזרים. אחריה **בדיקה עצמאית**: המודל פותר שוב מהצילום ומשווה לתשובות.
4. **בקרת איכות**: עריכה של נוסח, סעיפים, פתרון, מחוון ושרטוטים, עם תצוגה מקדימה של הנוסחאות. יש כפתור "איזון אוטומטי" ופענוח מחדש של שאלה בודדת. ההפקה נחסמת עד שכל השגיאות תוקנו.
5. **הפקה**: Word ×3, PDF ×3, או קובץ ZIP אחד.

## מה חדש ב-5.4 — מנוע שרטוטים דטרמיניסטי
ה-AI כבר לא "מצייר". הוא רק מחלץ מבנה (נקודות, קטעים, סימונים, פונקציה, ערכים), והמנוע:
1. **מעדיף את נוסח השאלה:** פונקציה, יחסים גאומטריים (AC=BC, AB∥CD, ∠B=90°, אמצע) וערכי תרשים שכתובים בשאלה גוברים על מה שנקרא מהתמונה.
2. **לא מסיק מהמראה:** שוויון/מקבילות/זווית ישרה נאכפים רק מהטקסט או מסימון מפורש בשרטוט (השרטוט המקורי לרוב אינו לפי קנה מידה).
3. **פותר אילוצים** ומזיז נקודות מינימלית כדי שכל הנתונים יתקיימו בדיוק; אילוצים סותרים ← נפסל.
4. **אימות קשיח** לפני ציור: נקודה על עקומה נבדקת בהצבה, ביטוי ללא ערכים ממשיים, נקודות כפולות, סימונים על קטע שלא שורטט, תווית לא ודאית ועוד.
5. **ציור דטרמיניסטי** (SVG + PNG ב-300dpi): צירים עם חצים, חורים, קצוות פתוחים/סגורים, אסימפטוטות, סימוני זווית ישרה, שוויון ומקבילות.
6. **השוואה מבנית:** המנוע בודק שצויר בדיוק מה שבמפרט (אנטי-הזיה), ושהשחזור תואם את מה שנראה במקור (מספר נקודות, תוויות, סימונים, חיתוכים עם הצירים, קצוות). אי-התאמה קריטית חוסמת תמיד.
7. **מדיניות ביטחון שמרנית** (עודכנה ב-5.5: ‎≥0.94 תצוגה בביטחון גבוה; 0.85–0.939 אישור מורה; 0.70–0.849 טיוטה; מתחת — מקור; אין אישור אוטומטי).
8. **אישור מורה בשלב 4:** מקור ושחזור זה לצד זה, ✅ אשר / ✏️ ערוך / ↩️ מקור / 🗑 דחה, ועורכים לגאומטריה, לגרפים ולתרשימים. אישור קשור לגרסה המדויקת של השרטוט; כל עריכה מבטלת אותו.
9. **במסמך נכנס שחזור רק אם אושר.** בכל מקרה אחר, או אם משהו נכשל, נכנס השרטוט המקורי והמבחן ממשיך.
10. **חבילת ביקורת** בשלב 5: לכל שרטוט — מקור, מקור מנוקה, JSON, SVG, PNG, תוצאות אימות/השוואה/החלטה, ותיעוד אישורים ועריכות.

## מה חדש ב-5.3
גרסה זו מבוססת על "5.2-audited" (ראו `AUDIT_V5_2_HE.md`). השיפורים שלה נשמרו, ותוקנו הבעיות שנמצאו כשהיא הורצה בפועל.

**נשמר מהביקורת:**
- האימות העצמאי בודק גם את התאמת הנוסח לצילום וגם את דרך הפתרון, לא רק את התשובה הסופית.
- אימות חסר או כושל חוסם את ההפקה עד לאישור ידני של המורה.
- לכל סעיף נדרשת תשובה סופית מפורשת.
- שורש אי-זוגי מחושב נכון גם עבור x שלילי.
- שחזור שרטוט עם ביטחון נמוך מ-0.85 מוחלף אוטומטית בתמונת המקור.
- הקנבס עודכן ל-0.13.0, כך שלא נדרשת עוד עקיפה פנימית של Streamlit.
- עורך התמונה רץ כ-fragment, כך שגרירת מסגרת החיתוך מהירה יותר.
- שלב 4 מציג רק את השאלה הנבחרת.
- קובץ ה-ZIP נדחס בפועל.

**תוקן:**
- **כלי המחיקה קרס אצל כל משתמש**, כי הקוד העביר לקנבס 0.13 פרמטר (`display_toolbar`) שכבר לא קיים בגרסה הזו.
- **ביטוי כמו `9^9^9^9` הקפיא את השרת.** חישוב השורש האי-זוגי רץ לפני בדיקת גודל החזקה, וסדר הבדיקות הוחזר.
- **שלב 4 קרס** (`'שאלה 2' is not in list`) אחרי פענוח מחדש מוצלח של שאלה שנכשלה. תוויות הבורר קבועות עכשיו.
- **אחרי סיבוב או יישור הגלריה וכפתור "בטל" לא התעדכנו**, בגלל ה-fragment. הלחצנים מפעילים עכשיו רענון מלא.
- **האימות חסם כשהבודק כתב "א." או "סעיף א" במקום "א".** מזהי הסעיפים מנורמלים לפני ההשוואה.
- **תמונה מודבקת שנמחקה הייתה חוזרת**, כי רכיב ההדבקה שולח את ההדבקה האחרונה בכל ריצה.
- **הוחזר תיקון 5.2** (מעבר אוטומטי למודל אחר כש-Gemini עמוס, שגיאת 503), שלא נכלל בגרסה המבוקרת.

## מה חדש ב-5.2-audited
- **דיוק מתמטי:** שורשים ממשיים ממעלה אי-זוגית עובדים גם עבור ערכי x שליליים; נוספו בדיקות רגרסיה ל-`x^(1/3)`, `x^(2/3)` ו-`(x-2)^(1/3)`.
- **אימות fail-closed:** לכל סעיף נדרשת תשובה סופית ובדיקת אימות מפורשת של נוסח המקור, דרך הפתרון והתשובה. כשל/חוסר באימות חוסם הפקה עד לאימות ידני.
- **בדיקה עמוקה יותר:** הפתרון והבודק העצמאי משתמשים ברמת thinking גבוהה, והבודק מקבל גם את שלבי הפתרון ולא רק תשובות סופיות.
- **חיתוך ומחיקה מהירים יותר:** עורך התמונה רץ בתוך `st.fragment`, תצוגת העריכה נשמרת ב-cache, והקנבס עודכן לגרסה מודרנית ללא monkey-patch של Streamlit.
- **בקרת שרטוטים:** שחזור AI בביטחון נמוך מ-0.85 לא נכנס למסמך; נעשה fallback אוטומטי לתרשים המקור.
- **זיכרון וממשק:** היסטוריית undo צומצמה ל-3 תמונות מלאות, בשלב 4 נטענת רק השאלה הנבחרת, ותמונה שנמחקה ניתנת להעלאה מחדש באותו session.
- **יציבות מקבילית:** מעבר מודל לאחר 404/מכסה מתייחס למודל שבאמת נכשל ולא למודל ששונה בינתיים על-ידי worker אחר.
- **ZIP:** קבצי החבילה נדחסים בפועל ב-DEFLATE במקום להישמר ללא דחיסה.

## מה חדש ב-5.1 (בעקבות הרצה אמיתית)
- **כלי החיתוך והמחיקה הופיעו כחלון ריק בכל שאלה חוץ מהראשונה.** הרכיבים החיצוניים מודדים את גודלם כשהם מוסתרים בתוך אזור מקופל, ונשארים בגובה 0. שלב 2 בנוי עכשיו מבורר שאלות שמציג את השאלה הנבחרת פתוחה, בלי אזורים מקופלים או לשוניות, ולכן הכלים מוצגים בגודל מלא בכל שאלה.
- **השגיאה 429 RESOURCE_EXHAUSTED במפתח חינמי** (עד 5 בקשות בדקה):
  - בשגיאת 429 הראשונה המערכת קוראת מהשגיאה את המכסה ואת זמן ההמתנה, ומאטה את כל הבקשות בהתאם. מפתח בתשלום לא מואט.
  - בזמן ההמתנה סרגל ההתקדמות מציג "ממתין למכסת Gemini…".
  - אם המכסה היומית של מודל נוצלה, המערכת עוברת אוטומטית למודל Flash אחר, שלו מכסה נפרדת.
  - השגיאות מוצגות בהסבר קצר בעברית, והטקסט הטכני זמין בחלון נפתח.
  - כפתור חדש "נסה שוב רק את השאלות שנכשלו" חוסך במכסה.
  - בשלב 3 מוצגת הערכה של מספר הקריאות ושל משך הפענוח.
- בורר השאלות שומר על הבחירה גם אחרי העלאת תמונות. תוויות שמשתנות גרמו ב-Streamlit 1.64 לקריסה.

## מה תוקן לעומת V4
**חוסמים (V4 לא עבד):**
- ה-SDK של Gemini דחה את הסכמה (`additionalProperties`) עוד לפני השליחה, ולכן כל פענוח נכשל. הסכמה הוחלפה, ובדיקה אוטומטית מוודאת שה-SDK מקבל אותה.
- ב-5.1 כלי המחיקה תוקן זמנית באמצעות מתאם תאימות; ב-5.2 הוסר המתאם והחבילה עודכנה לגרסה מודרנית התואמת ל-Streamlit הנוכחי.
- "שמור ניקוי" היה שומר דף לבן. עכשיו רק האזור המסומן מולבן, ברזולוציה המלאה.
- תמונות שנמחקו חזרו מעצמן מרכיב ההעלאה.
- הנוסחאות נעלמו מה-PDF, כי `libreoffice-math` לא היה ב-`packages.txt`.

**אמינות ודיוק:**
- החיתוך והמחיקה לא מקטינים עוד את התמונה ל-900 פיקסלים.
- יישור אוטומטי חדש לפי פרופיל שורות: דיוק של כ-0.1° בצילומי טלפון עם צל, בלי תלות ב-OpenCV.
- הפענוח נעשה לכל שאלה בנפרד, כך שאין קטיעת פלט. יש ניסיונות חוזרים (429/503), מעבר אוטומטי בין מודלים ופענוח מחדש של שאלה בודדת.
- **בדיקה עצמאית של הפתרונות**: אי-הסכמה חוסמת את ההפקה עד שהמורה מאשר ידנית.
- תשובה מקוטעת (`MAX_TOKENS`) מזוהה ומנוסה שוב.
- ולידציה חדשה: התאמה בין המחוון לניקוד כל סעיף, כיסוי פתרון לכל סעיף ומזהי סעיפים כפולים.
- ניקוד ברירת מחדל שלא עבר את הוולידציה של המערכת עצמה (למשל 7 או 12 שאלות).
- עורכי הטבלאות לא מאבדים ולא משכפלים שורות במעבר בין שלבים.
- ההוראות לתלמיד לא נשארות עם מספר שאלות שגוי אחרי שינוי מבנה הבחינה.

**אבטחה:** הוסר ה-`eval` על פלט המודל. ביטויי הגרפים מפוענחים במפענח בטוח עם רשימה לבנה של שמות, והגנה מפני חזקות ענקיות.

**עברית ו-Word:**
- טקסט עברי במסמך מקבל מודגש וגודל נכונים (`bCs`, `szCs`).
- פסקאות RTL מיושרות לימין גם ב-Word וגם ב-LibreOffice, ופסקאות LTR מיושרות לשמאל.
- סדר רכיבי ה-XML נשמר לפי מבנה Office. בדיקות המאגר בודקות את מבנה ה-OOXML; מומלץ להשאיר ולידציית XSD מלאה גם ב-CI/טרום-הפצה.
- שורשים ווקטורים הומרו ל-OMML לא תקין. עכשיו 31 סוגי נוסחאות נבדקים אוטומטית.
- עברית בשרטוטים משוחזרים כבר לא הפוכה (matplotlib) ולא מוצגת כריבועים (PIL).
- A4, מספור עמודים "עמוד X מתוך Y", שורת שם תלמיד וכיתה, טבלת מחוון עם שורת סיכום, ושרטוט שנשמר יחד עם השאלה שלו באותו עמוד.
- בטופס התלמיד לא מופיעים פקודות GeoGebra, תיאורי שרטוט, נושא השאלה או אחוזים בתרשים עוגה, כי כל אלה עלולים לרמוז על התשובה.

## בדיקות
```bash
pip install -r requirements-dev.txt
python -m pytest -q tests                       # 301 בדיקות: מנוע, קבלה על שאלוני בגרות, ליבה, ממשק, Crop/Erase
python tests/make_fixtures.py                   # יוצר צילומי מבחן מדומים
E2E_STATE_FILE=/tmp/e2e_state.json streamlit run tests/run_mock_app.py --server.port 8599 --server.headless true
python -m playwright install chromium && python tests/e2e_browser.py   # בדיקת דפדפן מלאה
```
`tests/run_mock_app.py` מריץ את האפליקציה האמיתית עם Gemini מדומה, בלי מפתח ובלי חיוב. הוא שימושי גם להדגמה.
כדי לדמות את השכבה החינמית בזמן אמת: `MOCK_FREE_TIER=1 MOCK_FREE_TIER_RPM=5` (בנוסף ל-`E2E_STATE_FILE`).

### עצות למפתח חינמי
- מבחן של N שאלות עם אימות עצמאי צורך כ-2N קריאות. ב-5 קריאות בדקה, 4 שאלות לוקחות כ-2 דקות.
- כדי לחסוך במכסה אפשר לבטל את "אימות עצמאי" בשלב 3. אז לבדוק את הפתרונות בעיון בשלב 4.
- מכסות השכבה החינמית נקבעות על ידי Google ועשויות להשתנות. המצב העדכני מופיע ב-https://ai.google.dev/gemini-api/docs/rate-limits.
